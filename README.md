# Agentopia

Agentopia는 여러 GitHub 저장소의 AI 개발 활동을 판타지 RPG 월드로 보여주는 읽기 전용 웹앱입니다. 화면을 채우는 월드맵에 기본 왕국으로 **Agentopia**를 표시합니다. Commit Trail과 Videx는 필요할 때 추가할 수 있습니다. 왕국을 선택하면 Issue별 개발 파티, 메인·하위 퀘스트, PR 리뷰, Actions, CI 및 배포 상태를 확인할 수 있습니다. 상단의 `+` 버튼에서 GitHub 저장소 주소나 `owner/repo`를 입력하면 왕국을 추가할 수 있습니다. 계정 이름만 입력하면 저장소 목록에서 여러 개를 체크해 한 번에 추가할 수 있습니다.

메인 이슈는 번호가 붙은 길드장으로, 그 아래의 하위 이슈는 각각 파티로 표시합니다. 길드장이 열린 동안 완료된 하위 이슈도 표시합니다. 상위 이슈가 없는 열린 이슈는 독립 파티로 표시합니다. 왼쪽 아래 퀘스트 창에서는 추가된 모든 왕국에서 조회한 이슈와 독립 PR을 모아 보고 상세를 열 수 있습니다. 캐릭터 범례는 오른쪽 아래에 표시합니다. 각 파티는 GitHub Actions, Codex, Claude, Release의 2×2 기호와 이슈 번호를 표시합니다. 현재 단계와 기록에 따라 담당 기호를 강조합니다. 마우스를 올리면 담당 이름과 현재 작업을 확인할 수 있습니다. 담당을 확인할 수 없는 경우에는 작업 상태와 함께 담당 미확인으로 표시합니다. 개입이 필요한 이슈는 빨간 깃발로 표시하고, 실패 상태는 해당 파티에서 확인할 수 있습니다. 파티 상세에서 GitHub Actions는 파티장으로, Release는 배포 담당인 포탈 관리자로 표시합니다.

연결된 이슈가 없는 열린 PR은 독립 퀘스트로 표시합니다. GitHub 봇 작성 계정이나 최신 커밋의 제출된 리뷰가 확인되면 해당 캐릭터를 표시합니다. 이슈 연결은 자동화 브랜치와 PR 본문의 종료 참조를 사용하며, 토큰이 있으면 GitHub에 등록된 연결도 조회합니다.

## 로컬 실행

Node.js 24와 npm이 필요합니다.

```bash
npm ci
npm run dev
```

Vite가 표시한 주소를 열면 됩니다. 개발 서버와 Vercel 배포가 같은 `/api/github` 핸들러를 사용합니다.

```bash
npm test
npm run build
npm run format:check
```

## GitHub 연결

공개 저장소는 토큰 없이 조회할 수 있습니다. GitHub의 비인증 API 한도를 초과하거나 비공개 저장소를 보려면 **GitHub 연결**에서 대상 저장소에만 접근할 수 있는 fine-grained PAT를 입력합니다. 저장소의 **Issues, Pull requests, Actions, Deployments**에 읽기 권한을 부여합니다. GitHub에서 자동으로 부여하는 Metadata 읽기 권한도 사용합니다.

토큰을 입력한 탭은 자신의 권한으로 GitHub를 조회합니다. 토큰은 브라우저 메모리에만 두고, 서버리스 함수는 해당 요청의 GitHub API 호출에만 사용합니다. 신뢰할 수 있는 Agentopia 배포에서만 토큰을 연결하세요. 연결 해제 또는 페이지 새로고침 시 토큰이 지워집니다. 상단 티켓을 눌러 토큰을 관리합니다. 토큰을 입력하면 티켓이 채워지고 저장소 추가 창이 열립니다. 관리 창에서 저장소 접근 확인과 인증·권한 상태를 볼 수 있습니다.

공개 저장소 목록은 브라우저에 저장합니다. 비공개 저장소는 토큰으로 접근을 확인한 현재 탭에서만 유지하며, 토큰을 바꾸거나 연결을 해제하면 목록에서 제거됩니다. 추가한 왕국을 선택하면 상세에서 월드맵에서 제거할 수 있습니다.

탭이 표시된 동안 토큰이 있으면 20초, 익명으로는 60초 간격으로 갱신합니다. 탭으로 돌아오면 즉시 조회합니다. 월드맵 상단의 갱신 아이콘을 누르면 수동으로 조회합니다. 버튼 배경은 다음 자동 갱신에 가까워질수록 아래에서 위로 채워집니다. 익명 조회는 서버에서 최대 60초간 재사용하며, 수동 새로 고침은 최근 요청에서 15초가 지났으면 캐시를 건너뜁니다. GitHub 요청 한도에 도달하면 재시도 시각까지 기존 응답을 사용합니다. 최근 갱신된 Issue·PR, 최근 Actions 실행과 상태 댓글의 제한된 범위를 표시합니다. 요청 오류와 일부 데이터 누락은 화면에 표시합니다. 클라우드의 제한된 네트워크에서 실데이터를 조회하려면 `api.github.com` 접속이 필요합니다.

## 상태 판정

- 알려진 형식의 AI 개발 워크플로 실행 제목과 같은 저장소의 `ai/issue-<번호>-<개발자>` PR 브랜치를 Issue에 연결합니다. 최근의 `github-actions[bot]` 상태 기록을 사용하고 새 실행 또는 재시도보다 오래된 기록은 배제합니다.
- Commit Trail은 기록된 개발자에 맞춰 교차 리뷰 역할을 전환합니다. Videx는 현재 자동화의 Codex 개발과 Claude 리뷰를 표시합니다. 새로 추가한 저장소에서는 GitHub 기록에서 확인되는 개발자와 리뷰어를 표시합니다.
- CI는 PR 헤드 커밋과 브랜치 또는 PR 번호가 일치하는 실행을 표시합니다. 배포는 기록된 배포 SHA와 연결된 PR 머지 SHA가 일치할 때 퀘스트에 연결합니다. 연결을 확인할 수 있는 근거가 없는 배포·릴리스 이벤트는 지역에만 표시합니다.
- GitHub 하위 Issue 관계로 메인·하위 퀘스트를 표시하며 실제 상태 기록과 원본을 확인할 수 있습니다. 활동을 확인할 수 없는 Issue는 대기로 표시합니다.

## 배포

Vercel에서 GitHub의 Agentopia 저장소를 가져오고 Node.js 24 기반 Vite 프로젝트로 배포합니다. `vercel.json`이 빌드 명령과 출력 경로를 설정합니다. 별도 서버나 데이터베이스는 필요하지 않습니다.
