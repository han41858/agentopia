# Agentopia

Agentopia는 여러 GitHub 저장소의 AI 개발 활동을 판타지 RPG 월드로 보여주는 읽기 전용 웹앱입니다. 처음에는 월드맵에 **Agentopia**를 표시합니다. 모든 저장소를 같은 방식으로 추가하거나 제거할 수 있습니다. 왕국을 선택하면 Issue별 개발 파티, 메인·하위 퀘스트, PR 리뷰, Actions, CI 및 배포 상태를 확인할 수 있습니다. 상단의 `+` 버튼에서 GitHub 저장소 주소나 `owner/repo`를 입력하면 왕국을 추가할 수 있습니다. 계정 이름만 입력하면 아카이브된 저장소를 제외하고 최근 업데이트된 저장소부터 표시하며, 여러 개를 체크해 한 번에 추가할 수 있습니다.

녹색 월드맵의 성벽 안에는 성과 길드 본부, 열린 PR 시설, 상단의 유산 건축물이 놓입니다. 열린 이슈는 성벽 밖 필드에 나타나며, 열린 하위 이슈는 열린 보스 주변에 배치합니다. 닫힌 이슈와 PR은 지도에서 사라지고, 상세 기록과 누적 집계에서 확인할 수 있습니다. 월드맵은 페이지 전체를 스크롤해 탐색합니다.

실제 실행과 기록에 따라 Codex·Claude가 한 이슈의 모험가 파티를 이룹니다. 확인된 모험가는 현재 작업 대상이 입증된 시설에서 제작이나 검수 동작을 합니다. 시설과 연결되기 전의 모험가는 이슈 몬스터 주변에 표시합니다. 개입이 필요한 작업은 경고 테두리로 표시합니다. 상태나 집계가 바뀌면 표식이 잠깐 밝아집니다.

연결 PR의 고유 커밋이 쌓이면 몬스터가 일정한 크기까지 커집니다. 말풍선은 댓글, 룬은 리뷰를 나타냅니다. 수정 요청과 승인은 서로 다른 봉인으로 표시하며, 재오픈이 확인되면 몬스터에 부활 효과가 나타납니다. 활동 효과의 의미는 GitHub 기록의 양으로 한정됩니다.

이슈나 PR을 선택하면 고유 커밋 수, 이슈와 PR의 댓글 수, 리뷰 수를 각각 확인할 수 있습니다. 토큰 없이 조회하면 최근 PR 두 개의 커밋을 제한적으로 가져옵니다. 상세에서 추가 기록을 요청하며, 조회 범위를 넘은 집계는 확인된 최솟값 또는 미확인으로 표시합니다.

PR 하나는 왕국의 시설 하나로 표시됩니다. 제목 맨 앞의 GitMoji로 대장간·성벽 수리 현장·정원·도서관·훈련장·기계 공방·정비소·경비탑·릴리즈 포탈을 고르며, 인식할 수 없으면 기본 공방을 사용합니다. 시설의 가동 및 검수 상태에는 실제 GitHub 기록을 사용합니다. 머지하거나 취소한 PR은 왕국 상세의 시설 이력으로 이동합니다. 다시 열면 지도에 표시합니다. 배포 상태는 왕국 상세의 배포 기록에서 확인할 수 있습니다.

몬스터나 시설을 선택하거나 가리키면 서로 연결된 대상을 함께 강조합니다. 이슈와 연결되지 않은 PR도 독립 시설로 표시합니다. 이슈 연결은 자동화 브랜치와 PR 본문의 종료 참조를 사용하며, 토큰이 있으면 GitHub에 등록된 연결도 조회합니다.

활동 중인 저장소는 기본 20초(토큰 연결) 또는 60초 간격으로 갱신합니다. 변화가 없는 저장소는 각각 최대 5분까지 간격을 늘리고, 비활성 탭에서는 조회를 더 늦춥니다. 새로고침 버튼은 대기 시간을 건너뜁니다. 공개 REST 응답은 서버 메모리에서 ETag로 재검증하며, 인증 응답은 서버에 저장하지 않고 같은 토큰의 동시 요청만 합칩니다. 상세 화면에서는 이미 열어 본 활동 탭을 다시 선택해도 같은 기록을 재요청하지 않습니다.

GitHub API 디버깅은 기본으로 켜져 있습니다. 필요하면 `AGENTOPIA_GITHUB_DEBUG=0`으로 끌 수 있습니다. 서버 로그의 `agentopia.github` 항목에서 저장소·엔드포인트별 요청, 캐시 적중과 304, 페이지네이션 및 상태 코드 집계를 확인할 수 있습니다. 새로고침 버튼 아래에는 직전 갱신에서 소비한 Core API 한도 비율과 GitHub가 보고한 누적 사용률을 표시합니다. 사용률에는 같은 계정의 다른 API 활동도 포함될 수 있습니다. 로그에는 토큰과 응답 본문이 포함되지 않습니다.

왕국 성벽 안쪽 상단에는 완공 기념비(머지된 PR), 영웅의 전당(완료 사유로 종료된 이슈), 기록 보관소(전체 댓글), 현자의 서고(제출된 리뷰)가 자리합니다. 각 누적 수치가 확인되면 해당 건축물이 나타나며, 건물을 선택하면 수치와 출처를 확인할 수 있습니다. 유산은 30분 간격에 맞춰 조회합니다. 해결된 이슈 수와 공개 조회의 머지된 PR 수는 GitHub 검색 인덱스를 사용합니다. 댓글은 이슈·PR 대화 댓글과 PR 인라인 댓글을 합치며 리뷰 본문은 댓글 집계에서 제외합니다. 전체 리뷰 수는 토큰으로 조회한 PR 목록 한 페이지가 저장소 전체를 포함할 때 집계합니다. 확인할 수 없는 합계는 미확인으로 표시합니다.

## 로컬 실행

Node.js 24와 npm이 필요합니다.

```bash
npm ci
npm run dev
```

Vite가 표시한 주소를 열면 됩니다. 개발 서버와 Vercel 배포가 같은 `/api/github` 핸들러를 사용합니다.

```bash
npm test
npm run build
npm run format:check
```

## GitHub 연결

공개 저장소는 토큰 없이 조회할 수 있습니다. GitHub의 비인증 API 한도를 초과하거나 비공개 저장소를 보려면 **GitHub 연결**에서 대상 저장소에만 접근할 수 있는 fine-grained PAT를 입력합니다. 저장소의 **Issues, Pull requests, Actions, Deployments**에 읽기 권한을 부여합니다. GitHub에서 자동으로 부여하는 Metadata 읽기 권한도 사용합니다.

토큰은 해당 사이트의 브라우저 로컬 스토리지에 저장하며, 서버리스 함수는 각 요청의 GitHub API 호출에만 사용합니다. 토큰은 티켓에서 연결을 해제하거나 사이트 데이터를 지울 때 제거됩니다. 상단 티켓을 눌러 토큰을 관리합니다. 토큰을 입력하면 티켓이 채워지고 저장소 추가 창이 열립니다. 관리 창에서 저장소 접근 확인과 인증·권한 상태를 볼 수 있습니다.

공개 저장소와 접근을 확인한 비공개 저장소 목록은 토큰과 함께 같은 브라우저에서 복원됩니다. 토큰을 바꾸거나 연결을 해제하면 비공개 저장소가 목록에서 제거됩니다. 이슈와 PR 조회 결과는 저장하지 않습니다. 추가한 왕국을 선택하면 상세에서 월드맵에서 제거할 수 있습니다.

탭이 표시된 동안 토큰이 있으면 20초, 익명으로는 60초 간격으로 갱신합니다. 탭으로 돌아오면 즉시 조회합니다. 월드맵 상단의 갱신 아이콘을 누르면 수동으로 조회합니다. 버튼 배경은 다음 자동 갱신에 가까워질수록 아래에서 위로 채워집니다. 익명 조회는 서버에서 최대 60초간 재사용하며, 수동 새로 고침은 최근 요청에서 15초가 지났으면 캐시를 건너뜁니다. GitHub 요청 한도에 도달하면 재시도 시각까지 기존 응답을 사용합니다. 최근 갱신된 Issue·PR, 최근 Actions 실행과 상태 댓글의 제한된 범위를 표시합니다. 요청 오류와 일부 데이터 누락은 화면에 표시합니다. 클라우드의 제한된 네트워크에서 실데이터를 조회하려면 `api.github.com` 접속이 필요합니다.

## 상태 판정

- 알려진 형식의 AI 개발 워크플로 실행 제목과 같은 저장소의 `ai/issue-<번호>-<개발자>` PR 브랜치를 Issue에 연결합니다. 최근의 `github-actions[bot]` 상태 기록을 사용하고 새 실행 또는 재시도보다 오래된 기록은 배제합니다.
- 최신 실행 번호와 시도가 일치하고 현재 실행 중일 때만 모험가의 개발·재전투·리뷰를 강조합니다. 리뷰어 이름이 확인되지 않으면 리뷰 상태만 표시합니다.
- CI는 PR 헤드 커밋과 브랜치 또는 PR 번호가 일치하는 실행을 표시합니다. 배포는 기록된 배포 SHA와 연결된 PR 머지 SHA가 일치할 때 퀘스트에 연결합니다. 연결을 확인할 수 있는 근거가 없는 배포·릴리스 이벤트는 지역에만 표시합니다.
- GitHub 하위 이슈 관계로 보스와 하위 몬스터를 표시합니다. 자동화 실행이 확인되지 않은 열린 이슈도 몬스터로 조회됩니다.

## 배포

Vercel에서 GitHub의 Agentopia 저장소를 가져오고 Node.js 24 기반 Vite 프로젝트로 배포합니다. `vercel.json`이 빌드 명령과 출력 경로를 설정합니다. 별도 서버나 데이터베이스는 필요하지 않습니다.

GitHub에 `.github/rulesets/main.json` 룰셋을 적용하면 `main` 대상 PR을 병합하려면 `Vercel` 프리뷰 검사를 통과해야 합니다.
