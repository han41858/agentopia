# GitHub 연결과 데이터

## 저장소와 토큰

공개 저장소는 토큰 없이 조회할 수 있습니다. 상단 **+** 버튼은 저장소 URL, `owner/repo`, 계정 이름을 받습니다. 계정으로 검색하면 아카이브된 저장소를 제외하고 최근 업데이트 순으로 나열합니다. 왕국 상세에서 저장소를 지도에서 제거할 수 있습니다.

비공개 저장소를 보거나 인증된 API 한도를 쓰려면 티켓 버튼에서 fine-grained PAT를 입력하세요. 대상 저장소에 **Issues, Pull requests, Actions, Contents** 읽기 권한을 부여합니다. 기존 토큰으로 비공개 저장소의 릴리스·태그가 조회되지 않으면 해당 저장소의 Contents 읽기 권한을 확인하세요. 토큰을 입력하면 티켓이 채워지고 저장소 추가 창이 열립니다. 티켓을 다시 열면 인증 상태와 저장소 접근 여부를 확인할 수 있습니다.

토큰과 저장소 목록은 해당 사이트의 브라우저 로컬 스토리지에 보관됩니다. 토큰을 교체하거나 연결을 해제하면 비공개 저장소 목록이 지워집니다. 연결 해제 또는 사이트 데이터 삭제로 저장한 토큰을 지울 수 있습니다. 서버는 요청에 전달된 토큰을 그 요청의 GitHub 조회에 사용합니다.

## 갱신과 API 사용량

- 활동 중인 저장소는 토큰 연결 시 20초, 익명 조회 시 60초가 기본입니다. 변경이 없으면 저장소별로 최대 5분까지 간격을 늘리고, 비활성 탭에서는 더 늦춥니다. 탭 복귀 시 갱신을 다시 확인합니다.
- 새로고침 버튼의 배경은 다음 갱신까지 차오릅니다. 버튼을 누르면 대기를 건너뜁니다. 공개 응답은 최대 60초간 재사용하며, 수동 조회는 최근 요청에서 15초가 지나면 이 캐시를 건너뜁니다. 공개 REST 응답은 ETag로 재검증하고 인증 요청은 같은 토큰의 동시 요청만 합칩니다.
- 인증된 태그·릴리스 기록은 해당 브라우저 탭에서 같은 토큰과 저장소에 한해 2분간 재사용합니다. 수동 갱신은 즉시 다시 조회합니다.
- 버튼 아래 첫 비율은 직전 갱신의 Core API 소비율이고, 두 번째는 GitHub가 보고한 누적 사용률입니다. 누적 사용률에는 같은 계정의 다른 클라이언트도 포함됩니다. 갱신 비용을 확인할 수 없으면 마지막 확인값을 유지하며 툴팁에서 확인할 수 있습니다.
- 디버깅은 기본 활성화됩니다. 서버 로그의 `agentopia.github`에서 저장소·엔드포인트별 요청, 캐시 적중, 304 응답, 페이지네이션, 상태 코드를 확인할 수 있습니다. 로그에서 토큰과 응답 본문은 제외합니다. 디버깅을 끄려면 `AGENTOPIA_GITHUB_DEBUG=0`을 설정합니다.

## 이슈 팝업에서 활동 기록 보기

이슈 팝업의 고정 헤더에서 **이슈 #N**을 선택하면 GitHub 원본으로 이동합니다. 고유 커밋, 이슈 댓글, PR 댓글, 리뷰 집계를 선택하면 해당 기록을 펼칩니다. 연결된 PR이 여러 개라면 펼친 목록에서 원하는 PR을 선택하세요. `+`는 확인된 최솟값, `—`는 미확인을 뜻합니다. 상태의 근거 링크는 활동 기록을 펼치지 않아도 사유 바로 아래에서 열 수 있습니다. 이슈와 PR 팝업의 **GitHub Actions** 목록에는 실행마다 시작 일시(KST), 상태 배지, 실행 링크가 한 줄에 표시됩니다. 시작 시각이 없는 실행은 `—`로 표시하며 긴 목록은 스크롤할 수 있습니다.

## 조회 범위와 연결 근거

이슈·PR 팝업의 Actions 이력은 워크플로 종류나 상태와 관계없이 실행 시작 시각이 최신인 순서로 최대 8개를 표시합니다. 정렬에는 GitHub가 제공한 원본 시각을 사용하지만 화면에는 분까지만 표시합니다. 시작 시각이 같으면 기존 순서를 유지하고, 시작 시각을 모르는 실행은 뒤에 두고 `—`로 표시합니다.

이슈 상태를 계산하거나 누락된 봇 기록을 보완할 때 같은 실행 선택 기준을 사용합니다. 신뢰된 봇 기록의 `run` 또는 `runId`를 실행 ID로 읽고 시도 번호를 대조합니다. 작업 기록 없이 취소되거나 건너뛴 병렬 실행은 실제 작업을 가리지 않으며 Actions 이력에는 남습니다. 새 실행이나 재시도에는 이전 작업의 상태를 이어 붙이지 않습니다.

지도는 최근 변경된 이슈·PR과 최근 Actions 실행을 우선합니다. 익명 조회에서는 최근 PR 두 개의 커밋을 제한적으로 가져옵니다. 상세 화면을 열면 필요한 기록을 추가로 조회하고, 이미 연 활동 탭은 기록을 재사용합니다. 조회가 불완전하면 확인된 최솟값이나 미확인 상태를 표시합니다. 브랜치 목록은 첫 페이지와 열린 PR의 로컬 참조를 사용하며 자동 조회 간격은 최소 2분입니다. 첫 페이지에 모든 브랜치가 나오지 않으면, 왕궁을 결정하는 데 필요한 `main` 또는 `master`만 개별 확인합니다. 수동 갱신은 브랜치 목록도 확인합니다.

| 연결할 대상   | 사용하는 GitHub 기록                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이슈와 모험가 | 자동화 워크플로 실행 제목, 같은 저장소의 `ai/issue-<번호>-<개발자>` 브랜치, 최근 `github-actions[bot]` 상태 기록. 최신 실행 번호와 시도가 일치할 때 개발·리뷰 동작을 표시합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 이슈와 PR     | 자동화 브랜치, PR 본문의 이슈 종료 참조, 토큰으로 조회할 수 있는 GitHub 연결 정보                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| PR과 CI       | PR 헤드 커밋과 일치하고 브랜치 또는 PR 번호가 일치하는 실행                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 배포와 PR     | 릴리스와 태그를 각각 한 페이지(30건) 조회합니다. 릴리스 게시 시각과 태그 대상 커밋 시각을 기준으로 통합 정렬합니다. 인증 조회는 GitHub에서 커밋 시각순으로 30개를 선택하며, 익명 조회는 첫 페이지의 태그를 가장 최근 게시된 릴리스의 태그에서 시작해 대조합니다. 릴리스가 없거나 시각이 더 필요하면 조회한 태그를 시작점으로 사용합니다. 조상 커밋은 최대 두 번, 각 100개까지 조회합니다. 확인한 시각만 표시하고 시각 미확인 태그는 뒤에 둡니다. 범위 밖 릴리스의 커밋 보완은 익명 요청당 가장 최근 미확인 릴리스 한 건입니다. 조회한 릴리스의 태그 커밋이 PR 머지 커밋과 일치하면 이슈에 게시 기록을 연결합니다. |

유산은 현재 작업과 별도로 30분 간격으로 조회합니다. 해결된 이슈와 익명 조회의 머지된 PR 수는 GitHub 검색 인덱스를 사용합니다. 전체 리뷰 수는 인증된 PR 목록 한 페이지가 저장소 전체를 포함할 때 집계합니다. 전체 댓글에는 이슈·PR 대화 댓글과 PR 인라인 댓글이 포함되며 리뷰 본문은 제외됩니다.
